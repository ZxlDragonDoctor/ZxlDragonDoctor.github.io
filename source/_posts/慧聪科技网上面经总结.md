### **16. Redis如何部署的，主从模式中，从节点能写入数据吗？**

#### ✅ **Redis部署方式：**

1. **单机部署**：直接启动`redis-server`，适用于开发测试。

2. **主从部署（Master-Slave）**：

   - 主节点负责读写。

   - 从节点默认**只读**，用于备份和读扩展。

   - 配置方式：

     - 在从节点`redis.conf`中配置：

       ```
       replicaof <主节点IP> <主节点端口>
       ```

       

     - 或者在运行时使用命令：

       ```
       REPLICAOF <主节点IP> <主节点端口>
       ```

       

3. **哨兵模式（Sentinel）**：用于主从自动故障转移。

4. **集群模式（Cluster）**：数据分片，支持高可用和水平扩展。

#### ❗ **从节点能否写入数据？**

- **默认情况下，从节点是只读的**，不能写入。
- 如果强制写入（通过配置`replica-read-only no`），写入的数据不会同步到主节点，也不会同步到其他从节点，会造成数据不一致，**生产环境不建议**。

### **17. ConcurrentHashMap，区别，怎么实现线程安全？（JDK1.8前后）**

#### ✅ **JDK1.7 vs JDK1.8 区别：**

表格

复制

| 特性         | JDK1.7                        | JDK1.8                               |
| :----------- | :---------------------------- | :----------------------------------- |
| **数据结构** | 分段锁（Segment + HashEntry） | 数组 + 链表 + 红黑树                 |
| **锁机制**   | 每个Segment一把锁             | 使用CAS + synchronized锁住链表头节点 |
| **并发度**   | 受Segment数量限制（默认16）   | 更高，支持更多线程并发               |
| **查询性能** | 链表过长时性能下降            | 链表长度>8转红黑树，查询O(log n)     |

#### ✅ **线程安全实现原理：**

- **JDK1.7**：
  - 使用**分段锁（Segment）**，每个Segment继承`ReentrantLock`，锁粒度较粗。
- **JDK1.8**：
  - 使用**CAS（Compare-And-Swap）**进行无锁插入。
  - 使用**synchronized**锁住链表或红黑树的**头节点**，锁粒度更细，并发性能更高。

#### ✅ **volatile的作用：**

- `Node.val`和`Node.next`使用`volatile`修饰，保证可见性。
- `table`数组也使用`volatile`，确保扩容时的可见性

### **5. Java 有哪些锁？**
| 锁类型            | 特点                   | 场景       |
| ----------------- | ---------------------- | ---------- |
| **synchronized**  | JVM 内置，可重入       | 低并发     |
| **ReentrantLock** | 可重入、可中断、公平锁 | 高并发     |
| **ReadWriteLock** | 读写分离               | 读多写少   |
| **StampedLock**   | 乐观读锁               | 读远大于写 |
| **自旋锁**        | 循环等待，不阻塞       | 短任务     |

### **9. synchronized 原理**
- **对象头 Mark Word**：存储锁标志位、线程 ID。
- **Monitor**：每个对象关联一个 Monitor，通过 `monitorenter/monitorexit` 指令加锁。
- **锁升级**：无锁 → 偏向锁 → 轻量级锁 → 重量级锁。

---

### **10. 偏向锁**
- **偏向第一个获取锁的线程**，后续该线程再次进入无需 CAS。
- **体现在对象头**：记录线程 ID，无竞争时性能最高。

---

### **11. 对象头存储的数据**
- **Mark Word**：锁状态、hashCode、GC 分代年龄、偏向线程 ID。
- **Klass Pointer**：指向类元数据（开启压缩指针后 4 字节）。
