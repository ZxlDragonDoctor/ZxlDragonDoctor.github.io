# 自由摄影师的最大收益 — 学习记录

> 来源：华为 OD 9/23 真题  
> 标签：排序 + 动态规划 + 0-1 背包  
> 语言：Java

---

## 1. 题目描述

小华是自由职业摄影师，接到 N 个拍摄订单。每个订单 i 包含：

| 属性 | 含义 |
|------|------|
| `times[i]` | 完成订单需要**连续工作**的天数 |
| `deadlines[i]` | 必须完成订单的截止日期 |
| `profits[i]` | 完成订单的收益 |

约束：

- 从第 **1** 天开始工作
- 一旦开始某个订单，必须**连续完成**，不能暂停或切换
- 每天只能处理**一个**订单
- 所有被选订单的完成时间 ≤ 各自截止日期
- 可以放弃任意订单

**目标**：在满足所有约束下，求最大总收益。

### 输入 / 输出

- 第一行：`times`，英文逗号分隔
- 第二行：`deadlines`，英文逗号分隔
- 第三行：`profits`，英文逗号分隔
- 输出：一个整数，最大总收益

约束：`1 ≤ N ≤ 500`，数组元素均为正整数。

### 示例

```text
输入
3,1,1,1
3,2,3,3
100,40,40,40

输出
120
```

解释：放弃 100 收益、要连做 3 天的大单，改做三个 1 天小单（40×3=120）。

---

## 2. 问题建模

本质是 **带截止日期的加权任务调度**：

```text
选哪些订单 + 按什么顺序做  →  在不超期的前提下收益最大
```

每天只有一个单位的「时间资源」，每个订单占用 `times[i]` 个连续单位，价值是 `profits[i]`。

---

## 3. 关键性质：按截止日期升序（EDD）

> **定理**：一定存在一个最优方案，其中被选订单按截止日期**从小到大**排列。

**交换论证**：

若相邻订单 i、j 满足 `deadline[i] > deadline[j]`，却先做 i 再做 j，交换为先 j 后 i：

- j 更早完成 → 对更紧的截止日更有利
- 原方案中两者都能完成，交换后完成时间只可能更早或不变（EDD 经典结论）

反复交换，总能得到一个截止日升序的可行最优解。

**推论**：排序后，顺序固定，只需决定「选或不选」→ **背包问题**。

---

## 4. 动态规划设计

### 状态定义

```text
dp[t] = 在已考虑的订单中，总工作天数恰好为 t 时，能获得的最大收益
```

- `t` 同时也是这批订单的**完成日**（从第 1 天连做到第 t 天）
- 初始化：`dp[0] = 0`

### 转移方程

对当前订单 `(time, deadline, profit)`：

```text
dp[day] = max(
    不做这一单：dp[day] 保持不变,
    做这一单  ：dp[day - time] + profit
)
```

可行性条件（已写入循环上界）：

```text
完成日 day ≤ 该单截止日 deadline
```

### 循环边界

```java
for (int day = deadline; day >= time; day--) {
    dp[day] = Math.max(dp[day], dp[day - time] + profit);
}
```

| 边界 | 原因 |
|------|------|
| 上界 `deadline` | 完成日不能超过截止日 |
| 下界 `time` | 至少需要 `time` 天才能做这一单；且 `day - time ≥ 0` |
| **倒序** | 保证 `dp[day - time]` 是加入本单之前的旧状态 → 每单至多用一次 |

### 答案

```text
max(dp[0], dp[1], ..., dp[capacity])
```

## 5. 完整 Java 代码

```java
import java.util.Arrays;
import java.util.Scanner;

public class SortAndDP {

    public static long solve(int[] times, int[] deadlines, long[] profits) {
        int n = times.length;
        long[][] jobs = new long[n][3]; // [工期, 截止日, 收益]

        long totalTime = 0;
        long maxDeadline = 0;
        for (int i = 0; i < n; i++) {
            jobs[i][0] = times[i];
            jobs[i][1] = deadlines[i];
            jobs[i][2] = profits[i];
            totalTime += times[i];
            maxDeadline = Math.max(maxDeadline, deadlines[i]);
        }

        // ① 按截止日期升序（EDD）
        Arrays.sort(jobs, (a, b) -> Long.compare(a[1], b[1]));

        // ② 容量：任何可行方案总工期 ≤ maxDeadline，也 ≤ totalTime
        int capacity = (int) Math.min(totalTime, maxDeadline);
        long[] dp = new long[capacity + 1];

        // ③ 0-1 背包
        for (long[] job : jobs) {
            int time = (int) job[0];
            int deadline = (int) job[1];
            long profit = job[2];

            for (int day = deadline; day >= time; day--) {
                dp[day] = Math.max(dp[day], dp[day - time] + profit);
            }
        }

        // ④ 取最大值
        long answer = 0;
        for (long value : dp) {
            answer = Math.max(answer, value);
        }
        return answer;
    }

    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int[] times = parseInts(sc.nextLine());
        int[] deadlines = parseInts(sc.nextLine());
        long[] profits = parseLongs(sc.nextLine());
        System.out.println(solve(times, deadlines, profits));
    }

    private static int[] parseInts(String line) {
        String[] parts = line.trim().split(",");
        int[] arr = new int[parts.length];
        for (int i = 0; i < parts.length; i++) {
            arr[i] = Integer.parseInt(parts[i].trim());
        }
        return arr;
    }

    private static long[] parseLongs(String line) {
        String[] parts = line.trim().split(",");
        long[] arr = new long[parts.length];
        for (int i = 0; i < parts.length; i++) {
            arr[i] = Long.parseLong(parts[i].trim());
        }
        return arr;
    }
}
```

## 6. 示例手算推演

输入：

```text
times     = 3,1,1,1
deadlines = 3,2,3,3
profits   = 100,40,40,40
```

**排序后：**

| 订单 | time | deadline | profit |
|------|------|----------|--------|
| A | 1 | 2 | 40 |
| B | 3 | 3 | 100 |
| C | 1 | 3 | 40 |
| D | 1 | 3 | 40 |

`capacity = min(6, 3) = 3`

### 处理 A（1, 2, 40）

```text
day=2: dp[2] = max(0, dp[1]+40) = 40
day=1: dp[1] = max(0, dp[0]+40) = 40
```

| day | 0 | 1 | 2 | 3 |
|-----|---|---|---|---|
| dp | 0 | 40 | 40 | 0 |

### 处理 B（3, 3, 100）

```text
day=3: dp[3] = max(0, dp[0]+100) = 100
（day < 3 进不了循环）
```

| day | 0 | 1 | 2 | 3 |
|-----|---|---|---|---|
| dp | 0 | 40 | 40 | 100 |

### 处理 C（1, 3, 40）

```text
day=3: dp[3] = max(100, dp[2]+40) = 100
day=2: dp[2] = max(40,  dp[1]+40) = 80    ← A+C
day=1: dp[1] = 40
```

| day | 0 | 1 | 2 | 3 |
|-----|---|---|---|---|
| dp | 0 | 40 | 80 | 100 |

### 处理 D（1, 3, 40）

```text
day=3: dp[3] = max(100, dp[2]+40) = 120   ← A+C+D
day=2: dp[2] = 80
day=1: dp[1] = 40
```

| day | 0 | 1 | 2 | 3 |
|-----|---|---|---|---|
| dp | 0 | 40 | 80 | **120** |

**答案 120**：第 1 天 A，第 2 天 C，第 3 天 D。

## 7. 为什么倒序（0-1 语义）

### 正序会重复使用同一订单

设 `time = 3, profit = 10`，正序 `day = 3, 4, 5...` 时：

```text
day=3: dp[3] = dp[0]+10 = 10     // 第 1 次
day=6: dp[6] = dp[3]+10 = 20     // dp[3] 本轮已更新 → 又用了一次！
```

变成**完全背包**。

### 倒序读到旧值

```text
写 dp[day] 依赖 dp[day - time]（更小下标）
倒序从大到小 → 小下标尚未被本轮更新 → 每单至多一次
```

| 背包类型 | 枚举方向 |
|----------|----------|
| 0-1 背包（每件至多一次） | **倒序** |
| 完全背包（可重复） | 正序 |

## 8. 实现易错点

### 8.1 收益下标写错（致命）

```java
jobs[i][2] = profits[2];   // ❌ 所有订单收益都变成第三个
jobs[i][2] = profits[i];   // ✅
```

- `n < 3`：数组越界
- `n ≥ 3`：答案必错

### 8.2 不排序

若不按 deadline 排序，「完成日是否超期」失去后效性，DP 会错。

### 8.3 正序枚举

变成完全背包，同一订单被多次计入。

### 8.4 dp 初始化

| 初始化 | 适用场景 |
|--------|----------|
| 全 0 | 收益全为正整数时可用（本题） |
| `-1` 表示不可达 | 更稳妥；有 0 / 负收益时必须 |

### 8.5 可行性条件

```java
// 错误：只看自己工期
if (time <= deadline)

// 正确：算上前面已占用的天数
// 即 day ≤ deadline，或 t + time ≤ deadline
```

### 8.6 收益用 `long`

多单加总可能超出 `int`。

## 9. 复杂度

| | |
|--|--|
| 时间 | `O(N log N + N × capacity)`，`capacity = min(Σtimes, maxDeadline)` |
| 空间 | `O(capacity)` |

`N ≤ 500`，`Σtimes` 在几十万量级内可过。

## 10. 可复用模板

```java
// 问题类型：选任务 + 有工期 + 有截止日 + 最大化收益
// 1. 按 deadline 升序排序
// 2. dp[t] = 总工期恰好为 t 的最大收益
// 3. 转移（倒序）：
//    for (day = deadline; day >= cost; day--)
//        dp[day] = max(dp[day], dp[day - cost] + value);
// 4. 答案 = max(dp)
```

**三个记忆点**：

1. **先按 deadline 排序**（EDD）
2. **倒序枚举 day**（0-1，不重复用）
3. **上界用 deadline**（完成日 ≤ 截止日）

---

## 11. 与 0-1 背包对照

| 概念 | 经典 0-1 背包 | 本题 |
|------|---------------|------|
| 物品 | 重量 `w`、价值 `v` | 工期 `time`、收益 `profit` |
| 容量 | 固定 `C` | 受 `deadline` 限制，上界 `day ≤ deadline` |
| 约束 | 总重 ≤ C | 总工期 = 完成日 ≤ 截止日 |
| 转移 | `dp[j] = max(dp[j], dp[j-w]+v)` | `dp[day] = max(dp[day], dp[day-time]+profit)` |
| 枚举 | 倒序 | 倒序 |

## 13. 一句话总结

> 按截止日期排序后，问题退化为「带体积（工期）的 0-1 背包」，体积还多一个上界约束（完成日 ≤ 截止日）；把约束写进循环上界，倒序转移取 `max(dp)` 即可。
