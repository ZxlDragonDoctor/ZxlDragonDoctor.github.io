# 分割等和子集：从访问标记到上一轮状态

## 题目与参考链接

- **力扣题目**：[416. 分割等和子集](https://leetcode.cn/problems/partition-equal-subset-sum/)

本文以“分割等和子集”为例，介绍 0/1 背包的状态定义、状态转移和空间优化，重点比较复制数组后的正序更新与原地倒序更新，并分析全局访问标记的局限。

> 适用条件：`nums` 是非空正整数数组，总和可以安全存入 Java 的 `int`。本文讨论的是每个数组位置最多选一次的 0/1 背包问题。


## 一、核心结论

**每一轮，是给每个旧组合一次“选或不选当前元素”的机会，而不是把当前元素反复加入刚生成的新组合。**

因此：

- **上一轮状态**：只考虑了前面的元素，还没有考虑当前这个元素。
- **本轮转移**：在旧组合的基础上，不选当前元素，或者选当前元素一次。
- **不能直接使用本轮新产生的状态继续选当前元素**：那个状态可能已经用过它，再选就重复了。
- **`prev` 复制法**：把旧状态单独保存，读取 `prev`，写入 `dp`。
- **倒序更新法**：不复制数组，通过更新顺序，保证要读取的旧值还没有被覆盖。

注意：这里的“同一个元素”是指**同一个数组位置**。数组 `[2, 2]` 有两个不同的元素，可以各选一次；数组 `[2, 6]` 只有一个 `2`，不能把这个 `2` 选两次。

## 二、把题目转化成“能否凑出目标和”

题目要求：把数组分成两个子集，使两边的元素和相同。

设整个数组的元素和为 `sum`。

1. 如果 `sum` 是奇数，无法分成两个相等的整数和，直接返回 `false`。
2. 如果 `sum` 是偶数，令 `target = sum / 2`。
3. 只要找到一个和为 `target` 的子集，剩余元素的和也一定是 `target`。

于是问题变成：

> 从数组中选择一些元素，每个位置最多选择一次，能否让总和等于 `target`？

例如：

```text
nums = [1, 5, 11, 5]
sum = 22
target = 11

可以选择 {11}，剩余的是 {1, 5, 5}。
两边的和都是 11，结果为 true。
```

## 三、状态定义与初始化

`dp[j]` 表示：

> 从目前已经处理过的元素中，能否选出一些，使它们的和恰好等于 `j`。

初始化：

```java
boolean[] dp = new boolean[target + 1];
dp[0] = true;
```

- `dp[0] = true`：一个元素都不选，就能得到和 `0`。
- 其他位置初始为 `false`：还没有处理任何元素，无法凑出正数。

### 重要区别：`dp` 在记录可能性，不是在分配元素

`dp[2] = true` 只是在说“存在一种凑出 2 的方案”。

它**不表示**：“这个方案使用的数字被永久拿走了，其他方案不能再用。”

不同的 `dp[j]` 可以对应不同的候选组合。它们不需要互相排斥，也不是同时从数组里取走元素。

## 四、全局访问标记的局限

一种容易产生的误区是：某个元素一旦参与了状态更新，就将其全局标记为已使用。以下为这种思路的伪代码，仅用于说明问题，并非可直接运行的 Java 实现：

```java
if (可以用 nums[k] 更新某个状态) {
    vist[k] = true;
}
```

问题在于：全局 `vist[k]` 只记录“这个元素用过了”，却不知道“在哪个候选组合中用过了”。

### 4.1 两个合法方案，会被全局标记错误地互相限制

假设已经处理过数字 `1`，现在处理数字 `2`，并且目标容量至少为 `3`。

下面两个转移都合法：

```text
旧组合 {}  + 当前的 2 -> {2}     对应 dp[2] = true
旧组合 {1} + 当前的 2 -> {1, 2}  对应 dp[3] = true
```

这两个组合中的 `2` 都只出现一次。

但如果更新 `dp[2]` 后，就把当前的 `2` 全局标记为已使用，那么 `{1, 2}` 这个合法候选方案也会被禁止。

**禁止的是同一方案内重复选取同一元素，不是禁止同一元素出现在不同候选方案中。**

### 4.2 反例：全局标记导致合法组合遗漏

考虑如下错误策略：外层按目标和从小到大遍历，内层扫描数组；跳过已被标记的元素，并在某个元素成功参与一次更新后将其全局标记。即使循环变量和跳过逻辑均正确，这种策略仍会遗漏合法组合。

输入：

```text
nums = [1, 2, 3, 4]
target = 5
```

可能发生的过程：

| 当前目标和 | 更新状态所用的元素 | 全局结果 |
| --- | --- | --- |
| 1 | 用 1 得到 `dp[1]` | 1 被标记 |
| 2 | 用 2 得到 `dp[2]` | 2 被标记 |
| 3 | 用 3 得到 `dp[3]` | 3 被标记 |
| 4 | 用 4 得到 `dp[4]` | 4 被标记 |
| 5 | 所有元素都被标记 | 无法继续更新 |

这样会返回 `false`，但实际上 `{1, 4}` 和 `{2, 3}` 都能凑出 `5`。

### 4.3 访问标记的适用范围

访问标记并非在所有算法中都不适用，关键在于它是否与具体的候选路径关联。

在回溯中，如果访问标记属于**当前搜索路径**，并在回退时撤销，就能表达当前组合选过哪些元素。

回溯的路径级标记与动态规划的状态汇总属于不同的管理方式，不能直接用一个全局 `vist` 替代本文一维布尔 `dp` 的元素使用约束。

## 五、上一轮状态的定义

以下为循环结构示意，省略号表示尚未展开的循环边界；完整可运行代码见第十节：

```java
for (int num : nums) {
    // 一次外层循环：处理当前这个元素
    for (int j = ...; ...; ...) {
        // 一次内层循环：计算一个目标和
    }
}
```

本文的“一轮”指**外层循环处理一个元素**，不是内层循环的一次 `j` 更新。

例如 `nums = [1, 2, 5]`：

| 阶段 | 已经允许参与选择的元素 |
| --- | --- |
| 初始化 | 没有元素 |
| 处理完第 1 个元素 | `[1]` |
| 处理完第 2 个元素 | `[1, 2]` |
| 处理完第 3 个元素 | `[1, 2, 5]` |

正在处理第 2 个元素 `2` 时：

- 上一轮：只使用 `[1]` 的选择结果。
- 本轮：把当前 `2` 的“选或不选”加入考虑。

因此，上一轮的所有组合都保证**没有使用过当前这个 `2`**。

## 六、为什么要读取上一轮状态？

先看状态转移：

```java
dp[j] = prev[j] || prev[j - num];
```

其中：

- `prev[j]`：不选当前元素，之前就能凑出 `j`。
- `prev[j - num]`：之前能凑出 `j - num`，**再选当前元素一次**，得到 `j`。

核心是：**这个转移本身已经包含一次“选择当前元素”的动作。**

所以，作为起点的组合必须还没有用过当前元素；否则再加一次，就会重复。

### 6.1 用 `[2, 6]` 看清重复选择

```text
nums = [2, 6]
sum = 8
target = 4
```

正确结果是 `false`，因为没有任何子集的和是 `4`。

但如果处理数字 `2` 时，正序读取刚更新的同一个 `dp` 数组，就会发生：

```text
旧方案 {}  + 当前这个 2 -> {2}      得到 dp[2] = true
新方案 {2} + 当前这个 2 -> {2, 2}   错误得到 dp[4] = true
```

第二步的起点已经用过当前这个元素，却又把它加了一次。

### 6.2 布尔状态不记录元素使用路径

`dp[j]` 只存 `true / false`，不会记录“是用了哪些元素才得到的”。

当本轮已经修改过一个位置时，仅凭它是 `true`，无法知道对应方案是否使用了当前元素。

**读取上一轮状态，就是从源头保证起点中没有使用当前元素。**

### 6.3 用二维定义把逻辑写完整

定义 `F(i, s)`：只使用前 `i` 个元素，能否凑出和 `s`。

当前元素是 `x = nums[i - 1]`。

```text
不选 x：F(i - 1, s)
选取 x：F(i - 1, s - x)，然后把 x 加进去
```

因此：

```text
当 s >= x：
F(i, s) = F(i - 1, s) OR F(i - 1, s - x)

当 s < x：
F(i, s) = F(i - 1, s)
```

初始条件：`F(0, 0) = true`，`F(0, s) = false`（`s > 0`）。

注意：两种选择都以 `i - 1` 为来源，因为要先排除当前元素，再决定本轮是否选它。

## 七、正序实现：复制上一轮状态

复制数组法将上一轮状态与本轮结果分别保存。内层循环只读取 `prev`、写入 `dp`，因此可以按目标和从小到大更新：

```java
for (int num : nums) {
    boolean[] prev = dp.clone();

    for (int j = num; j <= target; j++) {
        dp[j] = prev[j] || prev[j - num];
    }
}
```

### 7.1 `clone()` 做了什么？

```java
boolean[] prev = dp.clone();
```

这会创建一个独立的新数组，并把 `dp` 中的布尔值复制过去。

复制后：

- 刚开始，两份数组的内容相同。
- 修改 `dp`，不会修改 `prev`。
- 整个内层循环只读取 `prev`，不修改它。
- 等外层开始处理下一个元素时，才重新复制最新的 `dp`。

注意下面两句不同：

```java
boolean[] prev = dp.clone(); // 两个独立数组
boolean[] prev = dp;         // 指向同一个数组，不能隔离本轮修改
```

以上两句是对比示例，不应同时写在同一个作用域中。

### 7.2 逐步推演：已经处理完 1，现在处理 2

取 `nums = [1, 2, 5]`，`target = 4`。

已经处理完 `1`，开始处理 `2`，复制后是：

| 数组 / 下标 | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| `prev` | true | true | false | false | false |
| `dp` | true | true | false | false | false |

接下来正序更新：

| 内层步骤 | 实际计算 | 结果 | 对应含义 |
| --- | --- | --- | --- |
| `j = 2` | `prev[2] || prev[0]` | `dp[2] = true` | 可以选择 `{2}` |
| `j = 3` | `prev[3] || prev[1]` | `dp[3] = true` | 可以选择 `{1, 2}` |
| `j = 4` | `prev[4] || prev[2]` | `dp[4] = false` | 旧方案不能凑出 2，不能加当前 2 得到 4 |

第三步尤其重要：

```text
此时 dp[2] 已经是 true，但 prev[2] 仍然是 false。

读的是 prev[2]，不是 dp[2]。
所以不会用当前这个 2 凑出 2 后，又用它凑出 4。
```

这一轮结束后：

| 数组 / 下标 | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| `prev`：保持旧值 | true | true | false | false | false |
| `dp`：本轮结果 | true | true | true | true | false |

下一轮处理 `5` 时，重新复制这份最新的 `dp`。因为 `5 > target`，不能选择它来凑出目标范围内的和，内层循环不会执行。

### 7.3 为什么内层从 `num` 开始？

因为 `j < num` 时，当前正整数 `num` 不可能被选进和为 `j` 的组合；同时 `j - num` 也会是负数。

这些位置保持旧值即可，不需要更新。

## 八、倒序实现：在原数组上更新

倒序遍历通过调整更新顺序，使依赖位置在读取时仍保留上一轮的值，因此可以省去每轮的数组复制：

```java
for (int num : nums) {
    for (int j = target; j >= num; j--) {
        dp[j] = dp[j] || dp[j - num];
    }
}
```

### 8.1 为什么倒序读到的是旧值？

本题 `num > 0`，因此：

```text
j - num < j
```

当倒序循环正在更新 `dp[j]` 时：

- 大于 `j` 的位置，可能已经在本轮更新。
- `dp[j]` 自己，还没有在本轮更新。
- 小于 `j` 的位置，也还没有在本轮更新。

所以，右侧的 `dp[j]` 和 `dp[j - num]` 都还是上一轮结束时的值。

**不是程序查找了一份历史数据，而是这些位置的旧值还没被覆盖。**

### 8.2 再看处理数字 2 的顺序

仍然使用上一节的初始状态：

```text
下标：  0     1     2      3      4
dp：   true  true  false  false  false
```

倒序更新：

| 顺序 | 更新位置 | 读取位置 | 为什么没有重复 |
| --- | --- | --- | --- |
| 1 | `dp[4]` | `dp[2]` | 还没有执行到 `j = 2`，所以读到旧的 false |
| 2 | `dp[3]` | `dp[1]` | 读到上一轮的 true，得到 `{1, 2}` |
| 3 | `dp[2]` | `dp[0]` | 现在才更新 `dp[2]`，得到 `{2}` |

关键时间顺序：

```text
先读取旧 dp[2] 来计算 dp[4]
              |
              v
之后才把 dp[2] 更新为 true
```

当 `dp[2]` 变成新值时，`dp[4]` 已经算完，不会再回来用这个新值。

### 8.3 正序到底能不能用？

| 写法 | 是否正确 | 原因 |
| --- | --- | --- |
| 正序，读取同一个 `dp` 数组 | 不能保证正确 | 可能读取本轮刚生成的状态，重复使用当前元素 |
| 正序，读取复制出的 `prev` | 正确 | 只读旧状态，不受 `dp` 修改影响 |
| 倒序，读取同一个 `dp` 数组 | 正确 | 通过更新顺序保证依赖位置仍是旧状态 |

所以，不是“正序天然错误”，而是**原地更新时，正序不能保证读取旧状态**。

## 九、常见实现错误与边界检查

本节归纳独立于具体提交记录的实现陷阱。以下错误片段用于说明问题，不属于第十节的正确算法。

### 9.1 内层循环递增了错误变量

错误示例：假设 `i` 表示外层目标和，`j` 表示内层数组下标。

```java
for (int j = 0; j < len && !vist[j]; i++) {
    // ...
}
```

这里写成了 `i++`，应当是 `j++`。否则 `j` 不变，外层目标和 `i` 被错误推进，可能导致数组越界或错误结果。

循环变量修正只解决控制流程错误；若仍使用第四节所述的全局访问标记，状态设计依然不正确。

### 9.2 把 `!vist[j]` 写进条件，不是“跳过已访问元素”

```java
j < len && !vist[j]
```

一旦遇到已访问元素，整个内层循环就结束，不会继续检查后面的元素。

如果某个算法需要跳过元素，应使用类似 `continue` 的逻辑。但本题不应靠全局 `vist` 解决重复选择问题。

### 9.3 缺少奇偶判断

```java
if (sum % 2 != 0) {
    return false;
}
```

例如 `[1, 2]` 的总和为 `3`，整数除法会得到 `target = 1`。虽然能凑出 `1`，但不能据此判断可以等分。

### 9.4 成员变量在多次调用之间残留状态

如果将总和定义为成员变量：

```java
public int sum = 0;
```

如果同一个 `Solution` 对象多次调用方法，又没有清零，就会把前一次的和累加进去。

使用方法内的局部变量 `int sum = 0`，可使每次调用独立计算；若采用成员变量，则必须在方法开始时明确重置。

### 9.5 循环结构要与状态含义配套

本文的一维 0/1 背包写法是：

```text
外层：依次处理数组元素
内层：更新各个目标和的可达性
```

倒序优化成立的前提是外层按元素推进、内层按目标和更新。仅将某个目标和循环改为倒序，并不能替代对状态定义和循环层次的检查。

## 十、完整 Java 实现

以下两个版本二选一使用。两段代码都使用 `class Solution`，不要把它们原样放进同一个 Java 文件。

### 10.1 倒序版本：一维数组原地更新

```java
class Solution {
    public boolean canPartition(int[] nums) {
        int sum = 0;
        for (int num : nums) {
            sum += num;
        }

        if (sum % 2 != 0) {
            return false;
        }

        int target = sum / 2;
        boolean[] dp = new boolean[target + 1];
        dp[0] = true;

        for (int num : nums) {
            for (int j = target; j >= num; j--) {
                dp[j] = dp[j] || dp[j - num];
            }
        }

        return dp[target];
    }
}
```

### 10.2 正序版本：复制上一轮状态

```java
class Solution {
    public boolean canPartition(int[] nums) {
        int sum = 0;
        for (int num : nums) {
            sum += num;
        }

        if (sum % 2 != 0) {
            return false;
        }

        int target = sum / 2;
        boolean[] dp = new boolean[target + 1];
        dp[0] = true;

        for (int num : nums) {
            boolean[] prev = dp.clone();
            for (int j = num; j <= target; j++) {
                dp[j] = prev[j] || prev[j - num];
            }
        }

        return dp[target];
    }
}
```

### 10.3 复杂度

设数组长度为 `n`，目标和为 `T = sum / 2`。

| 版本 | 时间复杂度 | 辅助空间复杂度 | 区别 |
| --- | --- | --- | --- |
| 倒序更新 | `O(nT)` | `O(T)` | 不需要每轮复制数组 |
| 复制数组 | `O(nT)` | `O(T)` | 每轮额外复制一个长度为 `T + 1` 的数组 |

复制法每轮的复制也是 `O(T)`，因此总体时间复杂度仍是 `O(nT)`；同时需要使用的数组只有常数份，所以辅助空间仍是 `O(T)`。

### 11.2 复习问题

1. `dp[0]` 为什么初始化为 `true`？
2. 处理当前元素时，“上一轮”具体指什么？
3. 为什么不能用全局 `vist[k]` 表示数字是否已经使用？
4. `dp[j] = prev[j] || prev[j - num]` 的两项分别代表什么？
5. 为什么 `prev = dp` 不能替代 `prev = dp.clone()`？
6. 倒序更新到 `j` 时，为什么 `dp[j - num]` 还是旧值？
7. 如果读取独立的 `prev`，内层是否可以正序？
8. 两个值相等的元素是否可以分别使用？

### 11.3 参考答案

1. 空集的元素和是 `0`，所以和 `0` 可达。
2. 外层循环尚未处理当前元素时，只使用前面元素得到的状态。
3. 不同 `dp` 状态代表不同候选方案；同一个元素可以出现在不同候选方案中，只是不能在同一方案内重复使用。
4. 左边表示不选当前元素；右边表示旧组合凑出 `j - num`，再选当前元素一次。
5. 前者只是两个引用指向同一个数组；后者才创建内容相同但独立的新数组。
6. `num > 0`，所以 `j - num < j`；倒序时小下标还没被本轮更新。
7. 可以，因为所有转移都读取旧数组，不会读取本轮新值。
8. 可以，每个数组位置是一个独立元素，各自最多使用一次。

## 十二、总结：两种实现共享同一状态转移

```text
每个元素只能用一次
        |
        v
本轮只做一次“选或不选当前元素”的决定
        |
        v
选它之前，起点组合必须还没使用过它
        |
        v
从上一轮状态转移
        |
        +-- 复制旧数组：读 prev，写 dp
        |
        +-- 原地倒序：先读旧值，之后才覆盖它
```

**正序复制与原地倒序的共同目标，是让本轮选择只基于尚未使用当前元素的旧状态，从而保证每个元素在同一方案中最多出现一次。**
