## 泛型擦除

在Java中，**泛型擦除（Type Erasure）** 是编译器实现泛型的核心机制——**在编译阶段将泛型类型参数的信息“擦除”，仅保留原生类型（Raw Type）**，使生成的字节码与“无泛型的JDK 1.5之前的代码”兼容。这意味着：泛型仅在编译时提供类型检查，运行时JVM完全不知道泛型类型参数的存在。


### 一、泛型擦除的核心规则
编译器对泛型的擦除遵循两大规则，直接决定了泛型的运行时行为：


#### 1. 规则1：无约束的泛型参数 → 擦除为 `Object`
若泛型类型参数没有通过 `extends` 指定上限（如 `<T>`、`<K,V>`），编译后会直接替换为 `Object`。

**示例**：
```java
// 泛型类定义
public class Box<T> {
    private T value;
    public T getValue() { return value; }
    public void setValue(T value) { this.value = value; }
}
```

**编译后擦除结果**（等效于JDK 1.5前的代码）：
```java
// 泛型参数 T 被擦除为 Object
public class Box {
    private Object value;
    public Object getValue() { return value; }
    public void setValue(Object value) { this.value = value; }
}
```

- 编译时：`Box<String> box = new Box<>();` 会检查 `setValue` 的参数必须是 `String`，若传入 `Integer` 则编译报错；
- 运行时：JVM看到的只是 `Box` 类，`value` 的类型是 `Object`，无法区分 `Box<String>` 和 `Box<Integer>`。


#### 2. 规则2：有约束的泛型参数 → 擦除为“约束类型的上限”
若泛型参数通过 `extends` 指定了上限（如 `<T extends Number>`、`<E extends List>`），编译后会替换为这个“上限类型”（而非 `Object`）。

**示例**：
```java
// 泛型类定义（T 必须是 Number 或其子类）
public class NumberBox<T extends Number> {
    private T number;
    public T getNumber() { return number; }
    public void setNumber(T number) { this.number = number; }
    public double getDoubleValue() { return number.doubleValue(); } // 调用 Number 的方法
}
```

**编译后擦除结果**：
```java
// 泛型参数 T 被擦除为上限类型 Number
public class NumberBox {
    private Number number;
    public Number getNumber() { return number; }
    public void setNumber(Number number) { this.number = number; }
    public double getDoubleValue() { return number.doubleValue(); } // 无需改变（Number 本身有该方法）
}
```

- 关键优势：擦除为上限类型后，可直接调用上限类型的方法（如 `doubleValue()`），无需强制转型；
- 编译时检查：`NumberBox<Integer> box = new NumberBox<>();` 允许，`NumberBox<String> box = new NumberBox<>();` 编译报错（`String` 不是 `Number` 子类）。


### 二、泛型擦除的“副作用”：3个典型问题
由于擦除后泛型信息丢失，运行时会出现一些“反直觉”的问题，需通过特殊机制规避：


#### 1. 问题1：运行时无法区分泛型类型（如 `List<String>` 和 `List<Integer>`）
擦除后，所有泛型实例的类型都退化为原生类型（如 `List`），JVM无法通过 `instanceof` 判断其泛型参数。

**示例**：
```java
List<String> strList = new ArrayList<>();
List<Integer> intList = new ArrayList<>();

// 编译报错：无法通过 instanceof 检查泛型类型（运行时两者都是 List）
if (strList instanceof List<String>) { ... }

// 允许：只能检查原生类型 List
if (strList instanceof List) { ... }
```

- 原因：擦除后 `strList` 和 `intList` 的运行时类型都是 `ArrayList`（原生类型），泛型参数 `<String>` 和 `<Integer>` 已不存在；
- 结论：运行时无法判断一个集合的泛型具体类型。


#### 2. 问题2：不能创建泛型类型的实例（`new T()` 报错）
由于擦除后 `T` 被替换为 `Object` 或上限类型，编译器无法确定 `T` 的具体构造方法，因此禁止直接创建泛型参数的实例。

**错误示例**：
```java
public class Box<T> {
    public Box() {
        // 编译报错：Cannot instantiate the type T
        this.value = new T(); 
    }
}
```

**解决方案**：通过“类型令牌（Type Token）”或“工厂方法”间接创建实例：
```java
// 方案1：传入 Class 对象（类型令牌）
public class Box<T> {
    private T value;
    public Box(Class<T> clazz) throws InstantiationException, IllegalAccessException {
        this.value = clazz.newInstance(); // 通过 Class 对象创建实例
    }
}

// 使用：传入具体类型的 Class
Box<String> strBox = new Box<>(String.class);
```


#### 3. 问题3：泛型数组的创建受限（`new T[]` 报错）
与实例创建类似，擦除后无法确定 `T` 的具体类型，因此禁止直接创建泛型数组（但允许声明泛型数组引用）。

**错误示例**：
```java
public class Box<T> {
    public void createArray() {
        // 编译报错：Cannot create a generic array of T
        T[] array = new T[10]; 
    }
}
```

**解决方案**：
- 方案1：创建 `Object[]` 数组，强制转型为 `T[]`（需抑制unchecked警告）；
- 方案2：传入数组的 `Class` 对象，通过 `Array.newInstance()` 创建。

```java
// 方案2：通过 Array.newInstance() 创建泛型数组
public class Box<T> {
    public T[] createArray(Class<T> clazz, int size) {
        // 创建 clazz 类型的数组，长度为 size
        return (T[]) Array.newInstance(clazz, size);
    }
}

// 使用
Box<String> box = new Box<>();
String[] strArray = box.createArray(String.class, 5);
```


### 三、为什么Java要设计“泛型擦除”？
泛型是JDK 1.5引入的新特性，而擦除机制的核心目的是 **“向前兼容”**——确保JDK 1.5及以后的泛型代码，能与JDK 1.5之前的非泛型代码（如 `List` 而非 `List<String>`）无缝协作。

- 若采用“运行时保留泛型信息”的设计（如C#的泛型），则JVM需要重构，导致旧代码无法兼容；
- 擦除机制让泛型仅在编译时生效，运行时仍使用原生类型，完美兼容旧代码，但也带来了上述“副作用”。


### 四、总结
泛型擦除是Java泛型的“底层实现逻辑”，核心要点可概括为：
1. **擦除时机**：编译阶段，将泛型参数替换为 `Object`（无约束）或上限类型（有约束）；
2. **核心目的**：向前兼容JDK 1.5之前的非泛型代码；
3. **关键影响**：运行时丢失泛型信息，导致无法区分泛型类型、不能直接创建 `T` 实例和 `T[]` 数组；
4. **规避方案**：通过“类型令牌（Class<T>）”“工厂方法”等机制，间接实现泛型实例/数组的创建。

理解泛型擦除，是解决Java泛型相关问题（如unchecked警告、类型转换异常）的关键。







### 与通配符（`?`）的区别

方法签名中，`<T>`（类型参数）和`?`（通配符）都用于泛型，但用途不同：

- **`<T>`**：用于声明 “可重用的类型变量”，方法内部可多次使用该类型（如作为返回值、参数、局部变量类型）。
- **`?`**：用于 “不确定的单个类型”，通常作为参数类型，但方法内部无法直接使用该类型（只能调用`Object`的方法）。

#### 示例 4：对比类型参数和通配符

```java
// 1. 使用类型参数 <T>：方法内部可返回 T 类型
public <T> T getFirstElement(List<T> list) {
    return list.get(0); // 正确：返回 T 类型
}

// 2. 使用通配符 ?：方法内部无法返回具体类型（只能返回 Object）
public Object getFirstElementWithWildcard(List<?> list) {
    return list.get(0); // 只能返回 Object
}
```
