# 聚集索引和辅助索引(非聚集索引)

在 MySQL（InnoDB）里，“聚集索引”与“辅助索引”是两种**物理存储方式**完全不同的索引。  
理解它们差异的核心只有一句话：  
**聚集索引的叶子节点就是整行数据，辅助索引的叶子节点只是“主键值”——拿到主键后还得再回表。**

下面从 10 个维度逐层拆解，看完即可 100% 区分。

--------------------------------------------------
1. 定义与存在性
--------------------------------------------------
- 聚集索引（Clustered Index）  
  一张表**只能有 1 个**，InnoDB 把它当成数据本身来存放。  
  如果表定义了 PK，则 PK 就是聚集索引；  
  没 PK 就选第一个 UNIQUE+NOT NULL 键；  
  再没有就隐式生成 6 字节的 RowID 作为聚集索引。

- 辅助索引（Secondary Index）  
  又叫二级索引，**可以建多个**，包括普通 INDEX、UNIQUE、FULLTEXT、SPATIAL。  
  它们与数据行分离存放，仅起“指路”作用。

--------------------------------------------------
2. 叶子节点内容
--------------------------------------------------
- 聚集索引叶子：完整的行记录（所有列的值都在）。  
- 辅助索引叶子：索引列的值 + 对应行的**聚集索引键值**（通常是主键值）。  
  因此通过辅助索引查非索引列需要**回表（lookup）**：先走辅助索引拿到主键，再走聚集索引拿整行。

--------------------------------------------------
3. 逻辑结构图
--------------------------------------------------
聚集索引  
├─ 非叶子节点：主键值 + 页指针  
└─ 叶子节点：整行数据（主键顺序物理相邻）

辅助索引  
├─ 非叶子节点：索引列值 + 页指针  
└─ 叶子节点：索引列值 + 主键值  
（没有行数据）

--------------------------------------------------
4. 是否存储整行
--------------------------------------------------
- 聚集索引：是，它就是数据文件。  
- 辅助索引：否，只存索引列+主键。

--------------------------------------------------
5. 插入性能
--------------------------------------------------
- 聚集索引：  
  插入速度与主键顺序高度相关。  
  顺序主键（AUTO_INCREMENT） → 页分裂少，顺序写，性能高。  
  随机主键（UUID） → 页分裂频繁，产生碎片，性能差。

- **辅助索引：  
  插入时除了要写数据页，还要每建一个索引就多写一棵 B+ 树，随机 IO 成倍增加。  
  因此“索引越多，插入越慢”主要指辅助索引。**

--------------------------------------------------
6. 范围扫描性能
--------------------------------------------------
- 聚集索引：  
  叶子节点上数据**物理连续**，范围扫描（BETWEEN、>、ORDER BY PK）只需顺序读盘，极快。

- 辅助索引：  
  叶子节点只给主键，范围扫描后拿到一批主键，再**随机回表**（离散读聚集索引），随机 IO 多，性能下降。  
  覆盖索引（Using index）可避免回表，但前提是查询列全部包含在该辅助索引中。

--------------------------------------------------
7. 回表（lookup）成本
--------------------------------------------------
- 只有辅助索引才需要回表。  
- 回表次数 = 辅助索引叶子节点匹配到的行数。  
- 大偏移分页（LIMIT 100000,10）下，辅助索引先扫 100010 个主键再回表，性能暴跌；  
  此时让查询走**覆盖索引**或直接利用聚集索引排序可根治。

--------------------------------------------------
8. 覆盖索引（Using index）
--------------------------------------------------
- 辅助索引如果能满足查询的全部列（包括 WHERE、SELECT、ORDER BY），就**不需要回表**，Extra 显示 “Using index”。  
- 聚集索引天然覆盖所有列，但优化器不会把 “Using index” 写进 Extra，因为它就是数据。

--------------------------------------------------
9. 存储空间
--------------------------------------------------
- 聚集索引：1 份，大小 = 表数据本身。  
- 辅助索引：每建 1 个就多 1 棵 B+ 树，空间 ≈ (索引列长度 + 主键长度) × 行数 × 1.2（页头指针开销）。  
  主键越长，辅助索引膨胀越厉害——这是“UUID 当主键”最致命的副作用之一。

--------------------------------------------------
10. 典型 SQL 对比
--------------------------------------------------
表：user(id PK, name VARCHAR(30), age INT, addr VARCHAR(100), INDEX(name))

1) SELECT * FROM user WHERE id=5;  
   走聚集索引，1 次主键查找，0 回表，最快。

2) SELECT * FROM user WHERE name='Jack';  
   先走辅助索引 name → 拿到主键 id → 再回表取 addr、age，**2 次索引查找**。

3) SELECT id, name FROM user WHERE name>'Tom' ORDER BY name;  
   辅助索引 name 已包含 (name, id)，覆盖索引，**无需回表**，性能 ≈ 聚集索引。

--------------------------------------------------
一句话口诀
--------------------------------------------------
“聚集即数据，辅助只指路；  
  顺序插入快，随机插入慢；  
  范围扫连续，辅助多回表；  
  主键越短，辅助越瘦。”
