打家劫舍 I、II、III：从线性 DP 到树形 DP

打家劫舍系列的共同限制是：不能同时选择相邻的房屋。每道题的结构不同，状态定义也随之变化：

  1. I：房屋排成一条直线，用一维动态规划解决。
  2. II：房屋首尾相邻形成一个环，把问题拆成两个线性范围。
  3. III：房屋组成二叉树，对每个节点分别计算“偷”和“不偷”两种状态。

对应力扣题目

  • 198. 打家劫舍（House Robber）
  • 213. 打家劫舍 II（House Robber II）
  • 337. 打家劫舍 III（House Robber III）

一、共同思路：对每间房作“偷或不偷”的选择

处理当前房屋时有两种选择：

  • 不偷当前房屋：答案沿用前面房屋能得到的最大金额。
  • 偷当前房屋：不能偷相邻房屋，所以金额要加上“上上间房屋之前”的最优结果。

三、打家劫舍 II：房屋首尾相邻

新增的限制

房屋围成一个圆，第一间和最后一间也相邻。因此不能同时偷第一间和最后一间。题目页面

拆成两个线性问题

任何合法方案都不可能同时包含第一间和最后一间，所以它一定属于以下两种情况之一：

  1. 不偷最后一间：只考虑 [0, n - 2]。
  2. 不偷第一间：只考虑 [1, n - 1]。

四、打家劫舍 III：房屋组成二叉树

为什么不能直接套用数组递推？

数组题里相邻关系是下标相差 1；树题里题目规定父节点和子节点相邻。如果偷了当前节点，就不能偷它的左、右孩子；但可以偷孙子节点。

因此，单独记录“以这个节点为根的最大金额”不够。父节点需要知道子节点有没有被偷，所以每个节点要保留两个状态。

状态定义

对每个节点 node 定义：

  • f(node)：偷 node 时，以它为根的子树可得到的最大金额。
  • g(node)：不偷 node 时，以它为根的子树可得到的最大金额。

为什么使用后序遍历？

计算父节点状态时，需要先知道左右孩子的 f、g。所以要先递归处理左右子树，再计算当前节点，也就是后序遍历：左子树 → 右子树 → 当前节点。

五、三个问题的状态变化

题目 房屋结构 状态的核心信息 处理方式
打家劫舍 I 直线 前一个、前两个位置的最优金额 一维 DP，滚动两个变量
打家劫舍 II 首尾相连的环 是否排除第一间或最后一间 拆成两个线性区间，各自做 I
打家劫舍 III 二叉树 当前节点偷 / 不偷两种结果 后序遍历，树形 DP

六、常见错误

  1. 把 II 当成普通直线处理。 这样可能同时选择首尾两间。应拆成“去掉首间”和“去掉尾间”两个范围。
  2. III 每个节点只存一个最大值。 父节点需要知道孩子是否被偷，因此至少要保留“偷”和“不偷”两种状态。
  3. III 先计算父节点再递归孩子。 父节点的状态依赖孩子结果，应使用后序遍历。
  4. 滚动变量更新顺序错误。 先用旧的 prevTwo、prevOne 算出 current，再更新两个旧状态。
  5. 对空树没有定义结果。 空节点的两种 DP 状态都为 0，整棵树为空时答案为 0。

总结

三道题共享“当前元素选或不选”的决策。线性数组中，不偷当前房屋沿用前一状态，偷当前房屋则加上前两个位置的状态；环形结构通过排除一个端点拆成两种线性情况；树形结构则为每个节点保存偷与不偷两种结果，并用后序遍历自底向上计算。
