LeetCode 287：寻找重复数——三种解法学习记录

题目：287. 寻找重复数
官方题解：寻找重复数

一、题目条件

给定长度为 n + 1 的数组 nums，其中每个数字都在 [1, n] 范围内。恰好有一个不同的数字重复出现，重复次数至少为两次；其余数字最多出现一次。要求：

  • 返回重复的数字；
  • 不修改数组；
  • 额外空间为 O(1)。

这里的“一个重复数字”指只有一个数值重复，但它可以出现两次、三次或更多次。

二、先看懂题目为什么有重复数

数组有 n + 1 个位置，但可选的数字只有 n 种：1, 2, ..., n。因此至少有一个数字要被使用不止一次。这是抽屉原理。

例如有 5 个格子，却只有 4 种数字可填，至少有一种数字会重复。

三、方法一：值域二分查找

1. 二分的不是数组下标

数组没有排序，所以不能在数组下标上做普通二分。这里二分的是答案可能的范围 [1, n]。

选一个 mid，统计数组中有多少个数满足 nums[i] <= mid，记为 count：

  • count > mid：重复数在 [1, mid]；
  • count <= mid：重复数在 [mid + 1, n]。

2. 为什么计数能缩小范围？

区间 [1, mid] 只有 mid 个不同数字。

  • 如果重复数大于 mid，那么 [1, mid] 里的数都没有重复，所以 count <= mid。
  • 如果重复数不大于 mid，大于 mid 的数字最多有 n - mid 种。数组总长为 n + 1，所以小于等于 mid 的数至少有 n + 1 - (n - mid) = mid + 1 个，即 count > mid。

所以可以根据 count > mid 判断答案在哪一半。

3. 手算示例

搜索范围 mid nums[i] <= mid 的元素 count 下一步
[1, 4] 2 1, 2, 2 3 3 > 2，搜索 [1, 2]
[1, 2] 1 1 1 1 <= 1，搜索 [2, 2]

答案为 2。

4. Java 实现

  • 时间复杂度：O(n log n)
  • 额外空间：O(1)

四、方法二：逐位统计二进制

1. 和理想序列比较

如果没有重复，数字范围 1..n 中每个数字应该各出现一次。我们对每个二进制位分别统计：

  1. 1..n 中这一位有多少个 1；
  2. nums 中这一位有多少个 1。

如果 nums 中的数量更多，答案在这一位上就是 1；否则答案这一位是 0。

2. 为什么比较结果能还原重复数？

假设重复数出现 k 次。相对 1..n：

  • 重复数多出了 k - 1 份；
  • 值域里有 k - 2 个数字没有出现在数组中。

如果重复数当前位是 1，多出来的副本会增加这一位的 1 数量。即使缺失数字都能减少这一位的计数，最多也只能减少 k - 2，所以数组中的计数仍然至少多 1。如果重复数当前位是 0，它不会额外增加这一位的 1，缺失数字只会让计数减少或不变。

因此，比较每一位的计数，就能逐位得到重复数。

3. Java 实现

  • 时间复杂度：O(n log n)，需要统计的位数约为 log n。
  • 额外空间：O(1)

五、快慢指针的基础：环形链表（力扣 141 / 142）

在把快慢指针用到数组之前，先从真正的链表理解它。力扣 141. 环形链表 要判断链表是否有环；142. 环形链表 II 则要返回环的入口节点。287 题的第三种方法，本质上是把 142 题的“链表节点”换成“数组下标”。

1. 为什么快慢指针能判断链表有环？

慢指针每次走一步，快指针每次走两步：

如果没有环，快指针会走到 null，循环结束；如果有环，快指针进入环后会不断追赶慢指针。环的长度有限，而快指针每轮比慢指针多走一步，所以它们最终会在环内相遇。

2. 只有三个节点成环也能相遇

例如 head → A → B → head：

移动次数 slow fast
开始 head head
1 A B
2 B A
3 head head

三节点环中，快指针并不会“跳出”链表；走到 B 后，它的下一步就是 head。所以检查 fast != null && fast.next != null 后再走两步是安全的。

3. 如何从相遇点找到环入口？

第一次相遇的位置通常不是环入口。设：

  • a：从 head 到环入口的步数；
  • b：从环入口到第一次相遇点的步数；
  • c：环的长度。

相遇时，快指针走的距离是慢指针的两倍。两者距离差是 a + b，而它们相遇说明这个差刚好是环长的整数倍：

于是，从相遇点再走 a 步会到达环入口；从 head 出发走 a 步也正好到达入口。因此，把一个指针放回 head，让它和相遇点的指针都每次走一步，它们再次相遇的位置就是环入口。

第一阶段“相遇”解决的是有没有环；第二阶段“从头和相遇点同步走”解决的是入口在哪里。这两步要分开理解。

4. 使用哨兵节点时，怎样寻找环入口？

dummy 只是放在 head 前面的一个新节点，不改变原来的环；它让起点到环入口的距离多了一步。

第一阶段从 dummy 开始，到入口 A 要走两步：dummy → head → A。假设快慢指针在 A 相遇，第二阶段这样走：

步数 从 dummy 出发的指针 从相遇点 A 出发的指针
开始 dummy A
1 head B
2 A A

两者在入口 A 相遇。

下面是使用哨兵节点的完整实现：

不使用哨兵节点时，第一阶段从 head 开始，第二阶段也从 head 开始。使用哨兵节点时，第一阶段从 dummy 开始，第二阶段也从 dummy 开始。哨兵节点让起点到环入口的路径多出一步，因此第二阶段需要从 dummy 出发，才能与第一阶段的距离对应。

如果第一阶段从 dummy 开始，第二阶段却从 head 开始，在这个例子里两个指针会在环的 A、B 之间保持错开，无法在入口相遇。判断第二阶段从哪里开始时，要把 dummy 是否包含在起点到环入口的距离中考虑进去。

六、方法三：Floyd 快慢指针找环入口

这是最容易觉得“想不到”的方法。关键发现是：数组里的值都可以当作数组下标，因而可以把每个下标的值解释成“下一步要去的下标”。

1. 从题目条件得到“下一步”

数组长度是 n + 1，下标范围为 0..n；数组值范围为 1..n。所以对任意下标 i，nums[i] 都是一个有效下标。

3. 为什么一定会重复到某个下标？

每走一步都会到一个有效下标；不存在 null 或“走到末尾就停”的情况。可是下标只有 0..n 这 n + 1 种。不断走下去，访问次数超过可选下标数后，必然再次到达一个已经访问过的下标。

由于每个下标的下一步固定不变，一旦回到旧下标，后面的路径也会重复，于是形成环。

因此，路径可以先走一段不重复的“尾巴”，但不能无限走成一条直线，也不能停下来。

4. 为什么环的入口是重复数？

在上面的例子里，重复数 2 出现在下标 3 和 4：

也就是有两条边指向节点 2。从 0 出发的路径第一次进入环，也正好从 2 进入。

一般来说，从 0 出发的路径进入环时，环入口有两条入边：一条来自进入环之前的路径，另一条来自环内的前一个节点。这里确实会有环外路径：因为 nums[i] >= 1，没有边指向下标 0，所以从 0 出发不可能一开始就在环里。环入口对应的数字因此至少出现两次。题目保证只有一个不同的数字重复，所以环入口就是答案。

nums[i] 是下一个下标；重复数字则是被多个下标指向的节点。不要把数组中的“位置”和“位置里存的数字”混为一谈。

5. 重复数字出现三次以上也可以吗？

可以。出现次数只影响有多少条边指向重复数字，不会破坏“每个节点只有一个下一步”的规则。

6. 为什么“只有 n 个位置且数字不重复”不是同一种情况？

力扣题中的关键条件是：n + 1 个位置、值域 [1, n]。因此所有值都是有效下标，路径一定有下一步。

如果数组只有 n 个位置、下标为 0..n-1，但值域仍是 [1, n]，那么值 n 不是有效下标。此时 i → nums[i] 可能走出数组，不能沿用本题的“每一步都有效，所以必然绕回”的推理。

如果把位置重新标为 1..n，一组不重复的 1..n 数字形成的是一个排列。排列对应的图由若干个环组成，也不一定是一条直线。例如：

7. Floyd 两阶段代码

第一阶段：慢指针每次走一步，快指针每次走两步，它们会在环内相遇。
第二阶段：把慢指针放回下标 0，两个指针都每次走一步；它们再次相遇的位置就是环入口。

  • 时间复杂度：O(n)
  • 额外空间：O(1)

七、三种方法对比

方法 核心观察 时间复杂度 额外空间
值域二分 统计 <= mid 的元素数量 O(n log n) O(1)
按位统计 对比数组和 1..n 的每一位计数 O(n log n) O(1)
Floyd 快慢指针 把下标映射成下一步，寻找环入口 O(n) O(1)

  1. 二分法：我二分的是答案值域；count > mid 表示什么？
  2. 位统计：为什么要把 nums 和 1..n 对照？
  3. 快慢指针：为什么 nums[i] 可以当作下一个下标？
  4. 环的来源：为什么路径不能停？为什么有限下标会导致某个下标再次出现？
