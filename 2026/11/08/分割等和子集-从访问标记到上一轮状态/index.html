分割等和子集：从访问标记到上一轮状态

题目与参考链接

  • 力扣题目：416. 分割等和子集

本文以“分割等和子集”为例，介绍 0/1 背包的状态定义、状态转移和空间优化，重点比较复制数组后的正序更新与原地倒序更新，并分析全局访问标记的局限。

适用条件：nums 是非空正整数数组，总和可以安全存入 Java 的 int。本文讨论的是每个数组位置最多选一次的 0/1 背包问题。

一、核心结论

每一轮，是给每个旧组合一次“选或不选当前元素”的机会，而不是把当前元素反复加入刚生成的新组合。

因此：

  • 上一轮状态：只考虑了前面的元素，还没有考虑当前这个元素。
  • 本轮转移：在旧组合的基础上，不选当前元素，或者选当前元素一次。
  • 不能直接使用本轮新产生的状态继续选当前元素：那个状态可能已经用过它，再选就重复了。
  • prev 复制法：把旧状态单独保存，读取 prev，写入 dp。
  • 倒序更新法：不复制数组，通过更新顺序，保证要读取的旧值还没有被覆盖。

注意：这里的“同一个元素”是指同一个数组位置。数组 [2, 2] 有两个不同的元素，可以各选一次；数组 [2, 6] 只有一个 2，不能把这个 2 选两次。

二、把题目转化成“能否凑出目标和”

题目要求：把数组分成两个子集，使两边的元素和相同。

设整个数组的元素和为 sum。

  1. 如果 sum 是奇数，无法分成两个相等的整数和，直接返回 false。
  2. 如果 sum 是偶数，令 target = sum / 2。
  3. 只要找到一个和为 target 的子集，剩余元素的和也一定是 target。

于是问题变成：

从数组中选择一些元素，每个位置最多选择一次，能否让总和等于 target？

三、状态定义与初始化

dp[j] 表示：

从目前已经处理过的元素中，能否选出一些，使它们的和恰好等于 j。

初始化：

  • dp[0] = true：一个元素都不选，就能得到和 0。
  • 其他位置初始为 false：还没有处理任何元素，无法凑出正数。

重要区别：dp 在记录可能性，不是在分配元素

dp[2] = true 只是在说“存在一种凑出 2 的方案”。

它不表示：“这个方案使用的数字被永久拿走了，其他方案不能再用。”

不同的 dp[j] 可以对应不同的候选组合。它们不需要互相排斥，也不是同时从数组里取走元素。

4.3 访问标记的适用范围

访问标记并非在所有算法中都不适用，关键在于它是否与具体的候选路径关联。

在回溯中，如果访问标记属于当前搜索路径，并在回退时撤销，就能表达当前组合选过哪些元素。

回溯的路径级标记与动态规划的状态汇总属于不同的管理方式，不能直接用一个全局 vist 替代本文一维布尔 dp 的元素使用约束。

6.2 布尔状态不记录元素使用路径

dp[j] 只存 true / false，不会记录“是用了哪些元素才得到的”。

当本轮已经修改过一个位置时，仅凭它是 true，无法知道对应方案是否使用了当前元素。

读取上一轮状态，就是从源头保证起点中没有使用当前元素。

7.3 为什么内层从 num 开始？

因为 j < num 时，当前正整数 num 不可能被选进和为 j 的组合；同时 j - num 也会是负数。

这些位置保持旧值即可，不需要更新。

八、倒序实现：在原数组上更新

倒序遍历通过调整更新顺序，使依赖位置在读取时仍保留上一轮的值，因此可以省去每轮的数组复制：

8.1 为什么倒序读到的是旧值？

本题 num > 0，因此：

当倒序循环正在更新 dp[j] 时：

  • 大于 j 的位置，可能已经在本轮更新。
  • dp[j] 自己，还没有在本轮更新。
  • 小于 j 的位置，也还没有在本轮更新。

所以，右侧的 dp[j] 和 dp[j - num] 都还是上一轮结束时的值。

不是程序查找了一份历史数据，而是这些位置的旧值还没被覆盖。

8.3 正序到底能不能用？

写法 是否正确 原因
正序，读取同一个 dp 数组 不能保证正确 可能读取本轮刚生成的状态，重复使用当前元素
正序，读取复制出的 prev 正确 只读旧状态，不受 dp 修改影响
倒序，读取同一个 dp 数组 正确 通过更新顺序保证依赖位置仍是旧状态

所以，不是“正序天然错误”，而是原地更新时，正序不能保证读取旧状态。

九、常见实现错误与边界检查

本节归纳独立于具体提交记录的实现陷阱。以下错误片段用于说明问题，不属于第十节的正确算法。

9.1 内层循环递增了错误变量

错误示例：假设 i 表示外层目标和，j 表示内层数组下标。

这里写成了 i++，应当是 j++。否则 j 不变，外层目标和 i 被错误推进，可能导致数组越界或错误结果。

循环变量修正只解决控制流程错误；若仍使用第四节所述的全局访问标记，状态设计依然不正确。

9.2 把 !vist[j] 写进条件，不是“跳过已访问元素”

一旦遇到已访问元素，整个内层循环就结束，不会继续检查后面的元素。

如果某个算法需要跳过元素，应使用类似 continue 的逻辑。但本题不应靠全局 vist 解决重复选择问题。

9.3 缺少奇偶判断

例如 [1, 2] 的总和为 3，整数除法会得到 target = 1。虽然能凑出 1，但不能据此判断可以等分。

9.4 成员变量在多次调用之间残留状态

如果将总和定义为成员变量：

如果同一个 Solution 对象多次调用方法，又没有清零，就会把前一次的和累加进去。

使用方法内的局部变量 int sum = 0，可使每次调用独立计算；若采用成员变量，则必须在方法开始时明确重置。

10.3 复杂度

设数组长度为 n，目标和为 T = sum / 2。

版本 时间复杂度 辅助空间复杂度 区别
倒序更新 O(nT) O(T) 不需要每轮复制数组
复制数组 O(nT) O(T) 每轮额外复制一个长度为 T + 1 的数组

复制法每轮的复制也是 O(T)，因此总体时间复杂度仍是 O(nT)；同时需要使用的数组只有常数份，所以辅助空间仍是 O(T)。

11.2 复习问题

  1. dp[0] 为什么初始化为 true？
  2. 处理当前元素时，“上一轮”具体指什么？
  3. 为什么不能用全局 vist[k] 表示数字是否已经使用？
  4. dp[j] = prev[j] || prev[j - num] 的两项分别代表什么？
  5. 为什么 prev = dp 不能替代 prev = dp.clone()？
  6. 倒序更新到 j 时，为什么 dp[j - num] 还是旧值？

  8. 两个值相等的元素是否可以分别使用？

11.3 参考答案

  1. 空集的元素和是 0，所以和 0 可达。
  2. 外层循环尚未处理当前元素时，只使用前面元素得到的状态。
  3. 不同 dp 状态代表不同候选方案；同一个元素可以出现在不同候选方案中，只是不能在同一方案内重复使用。
  4. 左边表示不选当前元素；右边表示旧组合凑出 j - num，再选当前元素一次。
  5. 前者只是两个引用指向同一个数组；后者才创建内容相同但独立的新数组。
  6. num > 0，所以 j - num < j；倒序时小下标还没被本轮更新。
  7. 可以，因为所有转移都读取旧数组，不会读取本轮新值。
  8. 可以，每个数组位置是一个独立元素，各自最多使用一次。

十二、总结：两种实现共享同一状态转移

正序复制与原地倒序的共同目标，是让本轮选择只基于尚未使用当前元素的旧状态，从而保证每个元素在同一方案中最多出现一次。
