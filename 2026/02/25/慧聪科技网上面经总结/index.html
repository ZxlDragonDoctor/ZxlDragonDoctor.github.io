16. Redis如何部署的，主从模式中，从节点能写入数据吗？

✅ Redis部署方式：

  1. 单机部署：直接启动redis-server，适用于开发测试。

  2. 主从部署（Master-Slave）：

    • 主节点负责读写。

    • 从节点默认只读，用于备份和读扩展。

    • 配置方式：

      • 在从节点redis.conf中配置：

      • 或者在运行时使用命令：

  3. 哨兵模式（Sentinel）：用于主从自动故障转移。

  4. 集群模式（Cluster）：数据分片，支持高可用和水平扩展。

❗ 从节点能否写入数据？

  • 默认情况下，从节点是只读的，不能写入。
  • 如果强制写入（通过配置replica-read-only no），写入的数据不会同步到主节点，也不会同步到其他从节点，会造成数据不一致，生产环境不建议。

17. ConcurrentHashMap，区别，怎么实现线程安全？（JDK1.8前后）

✅ JDK1.7 vs JDK1.8 区别：

表格

复制

特性 JDK1.7 JDK1.8
数据结构 分段锁（Segment + HashEntry） 数组 + 链表 + 红黑树
锁机制 每个Segment一把锁 使用CAS + synchronized锁住链表头节点
并发度 受Segment数量限制（默认16） 更高，支持更多线程并发
查询性能 链表过长时性能下降 链表长度>8转红黑树，查询O(log n)

✅ 线程安全实现原理：

  • JDK1.7：
    • 使用分段锁（Segment），每个Segment继承ReentrantLock，锁粒度较粗。
  • JDK1.8：
    • 使用CAS（Compare-And-Swap）进行无锁插入。
    • 使用synchronized锁住链表或红黑树的头节点，锁粒度更细，并发性能更高。

✅ volatile的作用：

  • Node.val和Node.next使用volatile修饰，保证可见性。
  • table数组也使用volatile，确保扩容时的可见性

1. JDK1.8 新特性

  • Lambda 表达式、Stream API、方法引用（::）
  • 接口默认方法（default）、Optional、新的日期 API（LocalDateTime）
  • 元空间（替代永久代）、重复注解（@Repeatable）

面试话术：

“JDK1.8 最大的变化是函数式编程（Lambda+Stream），以及用元空间解决永久代 OOM。”

2. Stream 流常用操作

  • 中间操作：filter()、map()、distinct()、sorted()、limit()
  • 终端操作：forEach()、collect()、reduce()、count()、anyMatch()

示例：

3. ConcurrentHashMap 用来解决什么问题？

  • 解决 HashMap 的线程安全问题，替代 Hashtable。
  • 高并发读写场景（如缓存、计数器）。

面试话术：

“ConcurrentHashMap 通过 CAS + synchronized 锁桶头，实现高并发安全。”

4. 线程安全问题的现象

  • 数据不一致（如计数器少加）
  • 死循环（如 HashMap 死链）
  • NullPointerException（未同步初始化）

5. Java 有哪些锁？

锁类型 特点 场景
synchronized JVM 内置，可重入 低并发
ReentrantLock 可重入、可中断、公平锁 高并发
ReadWriteLock 读写分离 读多写少
StampedLock 乐观读锁 读远大于写
自旋锁 循环等待，不阻塞 短任务

6. 分布式锁方案

  • Redis 分布式锁（SETNX + EXPIRE）
  • RedLock（Redis 集群）
  • ZooKeeper（临时有序节点）
  • 数据库锁（悲观锁 FOR UPDATE）

7. SETNX 有超时时间吗？

  • 没有，必须配合 EXPIRE 或使用 SET key value NX EX 10。

8. 锁提前释放怎么办？

  • Redisson 看门狗：自动续期（默认 30s 续一次）
  • 方案：业务执行完手动释放（DEL key），或设置足够长的超时。

9. synchronized 原理

  • 对象头 Mark Word：存储锁标志位、线程 ID。
  • Monitor：每个对象关联一个 Monitor，通过 monitorenter/monitorexit 指令加锁。
  • 锁升级：无锁 → 偏向锁 → 轻量级锁 → 重量级锁。

10. 偏向锁

  • 偏向第一个获取锁的线程，后续该线程再次进入无需 CAS。
  • 体现在对象头：记录线程 ID，无竞争时性能最高。

11. 对象头存储的数据

  • Mark Word：锁状态、hashCode、GC 分代年龄、偏向线程 ID。
  • Klass Pointer：指向类元数据（开启压缩指针后 4 字节）。

12. Spring 单例以外的模式

  • 原型模式（@Scope("prototype")）
  • 请求作用域（request）
  • 会话作用域（session）
  • 全局会话（globalSession）

13. 原型模式使用场景

  • 有状态的 Bean（如每次请求需独立副本）
  • 示例：@Scope("prototype") + 多线程任务中避免共享状态。

14. Spring 默认单例的类

  • 所有 Bean 默认单例（@Component、@Service、@Repository）。

15. Bean 生命周期阶段

  1. 实例化（构造函数）
  2. 属性赋值（DI）
  3. 初始化（@PostConstruct、InitializingBean）
  4. 使用
  5. 销毁（@PreDestroy、DisposableBean）

16. 销毁时自定义逻辑

  • 注解：@PreDestroy
  • 接口：实现 DisposableBean.destroy()
  • 配置：destroy-method="cleanup"

17. @Transactional 参数

  • propagation（传播行为）
  • isolation（隔离级别）
  • timeout（超时时间）
  • readOnly（只读）
  • rollbackFor（指定回滚异常）

18. @Transactional 未回滚原因

  • 异常未抛出（被 catch）
  • 非 RuntimeException（需指定 rollbackFor）
  • 内部调用（绕过代理）

19. 内部调用事务失效原因

  • Spring 事务基于代理，同类内部方法调用不走代理，事务失效。

20. 代理对象核心机制

  • Spring AOP：基于 动态代理（JDK/CGLIB）
  • 核心方法：Proxy.newProxyInstance() 或 Enhancer.create()

21. 内部调用事务生效方案

  • 注入自身（@Autowired 代理对象）
  • **AopContext.currentProxy()**（需开启暴露代理）

22. getBean() 获取的是代理吗？

  • 是的，Spring 容器中存的是代理对象（单例池）。

23. @Transactional 的 AOP 体现

  • 切面：事务开启、提交、回滚。
  • 通知：@Around 拦截方法，执行 TransactionInterceptor。

24. Nacos 集群部署

  • 至少 3 个节点，持久化配置存 MySQL。
  • 集群模式：cluster.conf 配置所有节点 IP。

25. CAP 理论与 Nacos

  • CAP：一致性（C）、可用性（A）、分区容错（P）。
  • Nacos：默认 AP（牺牲一致性保证高可用），可切换 CP（Raft）。

26. 注册中心需要的功能

  • 服务注册/发现
  • 健康检查（心跳）
  • 负载均衡（客户端/服务端）
  • 故障剔除（超时剔除）

27. Nacos 动态刷新

  • @RefreshScope 或 @NacosValue
  • 原理：监听配置变更事件（长轮询），触发 Bean 重新绑定。

28. EXPLAIN 关键字段

字段 含义
type 查询类型（ALL/index/ref/range）
key 实际使用的索引
rows 扫描行数
Extra 额外信息（Using index/filesort）

29. 慢 SQL 优化方向

  • 索引优化（覆盖索引、最左匹配）
  • **避免 SELECT ***（减少回表）
  • 分页优化（延迟关联）
  • JOIN 优化（小表驱动大表）
  • 子查询转 JOIN

30. 事务隔离级别（补全）

  1. READ UNCOMMITTED
  2. READ COMMITTED
  3. REPEATABLE READ（MySQL 默认）
  4. SERIALIZABLE

31. JVM 常用启动参数

  • -Xmx（最大堆）
  • -Xms（初始堆）
  • -Xss（栈大小）
  • -XX:+PrintGCDetails（打印 GC 日志）
  • -XX:MetaspaceSize（元空间初始值）

32. Full GC 触发条件

  • 老年代空间不足
  • System.gc()
  • 元空间不足
  • 晋升失败（Survivor 放不下）

33. Full GC 会回收方法区/元空间吗？

  • 会，Full GC 会清理 元空间中无用的类加载器。

34. OOM 场景

  • 内存泄漏（如 ThreadLocal 未清理）
  • 大对象（如一次性加载大文件）
  • 递归过深（栈溢出）

35. 内存泄漏定位工具

  • jmap（生成 dump）
  • MAT（Memory Analyzer Tool）
  • VisualVM（实时监控）
  • Arthas（在线诊断）

  • JVM + MySQL + Spring：刷 《深入理解JVM》+《MySQL技术内幕》+《Spring实战》
  • 项目：提前准备 MQ 场景 + 分布式锁 + 事务失效 的坑。
  • 工具：Arthas + MAT + EXPLAIN 现场演示更加分！
